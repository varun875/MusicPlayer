
## 2025-02-23 - Optimize Compose LazyRow and AsyncImage Recomposition
**Learning:** In Jetpack Compose, directly passing URIs to `AsyncImage` in `LazyRow` items without explicit `remember`-ed `ImageRequest` objects with defined `.size()` and cache keys causes unnecessary image processing overhead and lags during scroll. Additionally, `items` blocks in `LazyRow` must use the `key` parameter to prevent excessive recomposition.
**Action:** When working with image loading in lists, always inject `key = { it.id }` in `items()` and use `val imageRequest = remember(context, item.id) { ImageRequest.Builder(context)...build() }` with explicit sizes before passing to `AsyncImage`.

## 2024-03-01 - [Jetpack Compose Inline ImageRequest Recomposition Bottleneck]
**Learning:** Instantiating Coil `ImageRequest.Builder` inline inside a Composable list item without memoizing it with `remember` triggers unnecessary allocations and request rebuilding. Relying on URI-only `.memoryCacheKey` and `.diskCacheKey` values is unsafe when the same image can be decoded at multiple sizes (e.g., list rows vs cards), because cache entries can collide and the wrong-sized bitmap may be reused; prefer Coil’s default data+size cache keys, or, if you must override them, include both the content URI and the requested size/scope in the key.
**Action:** Always wrap `ImageRequest` objects in a `remember` block using stable inputs such as the image URI and any relevant size/scope (e.g., `remember(context, item.imageUri, targetSize)`), and when specifying custom memory/disk cache keys, either rely on Coil’s default behavior by not overriding them, or ensure your keys include both the URI and the requested size/scope (for example, `"${item.imageUri}@$widthx$height"`), rather than using the raw URI alone.

## 2025-02-23 - Remove Explicit Cache Keys to Prevent Coil Cache Collisions
**Learning:** Overriding Coil's default `memoryCacheKey` and `diskCacheKey` without incorporating the requested image size or transformations causes severe performance regressions. If multiple UI components request the same URI at different sizes (e.g., a 144px thumbnail vs a 400px card) but use the same manual key (like `album_${id}_home`), Coil will encounter cache collisions. This breaks Coil's disk cache sharing mechanism, forcing redundant decodes of inappropriately sized bitmaps and increasing memory usage.
**Action:** Remove explicit `.memoryCacheKey` and `.diskCacheKey` lines entirely from `ImageRequest.Builder` calls. Rely on Coil's highly optimized default cache key generation, which natively factors in the image URI, size, and transformations to ensure safety and efficiency across the application.
